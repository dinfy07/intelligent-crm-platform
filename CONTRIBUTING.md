# Contribution and review workflow

This repository starts with AI-assisted preparation materials dated 19 October 2026. They require student and supervisor review. Do not present this baseline as weeks of individual student development.

1. Use your own identifiable GitHub account and author details. Do not share accounts or impersonate another member.
2. Create a real YouTrack task with responsible student, expected outcome, acceptance criteria, priority and deadline.
3. Map the local PLN key to the actual issue ID, then create codex/<actual-id>-description.
4. Commit coherent, descriptive changes. Include the actual task ID in commits and the PR description.
5. A PR explains behaviour, links the task and records checks and limitations. Another team member reviews before merge.
6. Link the actual commit/PR in YouTrack. Close the issue only when its acceptance criteria pass.
7. main is the reviewed baseline. Tag the selected checkpoint commit as pre-defense-1 after actual review and evidence checks. Never move submitted tags.

Proposed review rotation: Danial reviews UI integration; Akhmediyar reviews backend acceptance; Beybit reviews analysis-output usability. These are assignments, not records of reviews already performed.

Do not commit client records, interview identities, credentials or confidential screenshots. Use de-identified evidence only when permitted.
